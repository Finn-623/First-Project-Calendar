# AI 开发工具选择规范

## 1. 目的与适用范围

本文件用于固定 First-Project-Calendar 的开发工具分工、选择顺序和并发边界。

项目级安全、授权、测试、记录和 Git 规则以根目录 `AGENTS.md` 为准；工具专属规则不得降低这些要求。

## 2. 工具分工

### ChatGPT

适合：

- 需求梳理。
- 功能拆分。
- 产品设计。
- 架构讨论。
- 生成可复制给 Codex 或 Gemini 的完整指令。
- 成本和工具选择建议。

ChatGPT 默认不直接操作本地项目。

### Codex

Codex 是项目主要开发 Agent，适合：

- 跨文件功能开发。
- 路由、状态、服务和数据库调用修改。
- 测试编写。
- 文档更新。
- 经用户明确授权后的独立 Git commit。
- 上线前检查。

### GitHub Copilot

适合：

- 当前文件代码补全。
- 简单函数和类型补全。
- 小范围、经人工确认的修改。
- 解释当前代码。

不用于：

- 大范围自主重构。
- 数据库迁移。
- 独立完成完整功能并自动提交。

### Gemini CLI

默认适合：

- 只读检查。
- 代码解释。
- 第二意见。
- Codex 完成后的代码审查。
- 风险和遗漏检查。

只有用户明确授权后才能修改文件，具体限制见根目录 `GEMINI.md`。

### 终端人工操作

以下操作原则上由用户本人完成：

- Google、Supabase、Vercel 等账号登录。
- API Key 和 Secret 输入。
- 付费、Billing 和权限授权。
- 生产部署最终确认。
- 高风险数据库操作确认。

### 部署授权边界

- AI 可以进行部署前检查、生成部署步骤和准备命令。
- 预览环境或非生产部署仍需当前任务明确授权。
- Vercel、Supabase 等生产环境部署不得因为一般开发授权而自动执行。
- 生产部署必须在完成测试、版本记录和变更确认后，由用户进行最终确认。
- 只有用户针对本次生产部署单独、明确下达执行指令时，Codex 才可以执行。
- Gemini CLI 默认不得执行任何部署。
- 付款、Billing、账号授权、Secret 输入和高风险生产操作原则上由用户本人完成。

## 3. 固定选择顺序

默认流程：

1. ChatGPT 梳理需求并选择工具。
2. Codex 执行正式开发。
3. Copilot 辅助局部编辑。
4. Gemini 在完成后进行只读审查。
5. 用户确认后提交或发布。

任务不需要经过所有工具；简单任务应选择完成它所需的最少工具。

## 4. 成本规则

- 优先使用现有的 ChatGPT Plus、Codex 和 Copilot 能力。
- Gemini 主要作为低成本只读审查和备用工具。
- 不因为简单任务重复调用多个 Agent。
- 不建议为功能重叠的工具新增付费订阅。
- 环境配置和简单终端问题优先由 ChatGPT 指导用户手动完成。

## 5. 按任务规模选择

| 任务类型 | 默认工具 |
| --- | --- |
| 仅解释或规划 | ChatGPT |
| 单行或单函数补全 | GitHub Copilot |
| 单文件简单修改 | GitHub Copilot 或 Codex，按风险决定 |
| 跨文件正式功能 | Codex |
| 数据库、认证、权限和迁移 | Codex |
| 完成后的第二次审查 | Gemini CLI |
| 上线前完整检查 | Codex；必要时由 Gemini CLI 只读复核 |

## 6. 并发与交接限制

- 一个工作区同时只有一个主要写入工具。
- 其他工具在此期间只能只读，且不得与主要写入工具同时修改。
- 不允许多个 Agent 同时修改相同文件。
- 开始修改前以及切换工具前必须检查 Git 状态。
- 如果发现来源不明或超出当前任务范围的未提交修改，必须立即停止，并向用户确认这些修改是否来自其他 Agent 或正在进行的任务。
- 用户确认前，新工具不得覆盖、恢复、清理或继续修改相关文件。
- 工具不得声称能够可靠检测其他 Agent 或进程的实时工作状态；协作判断以 Git 状态、任务范围和用户确认为准。
- 交接时应说明已修改文件、已执行检查、未完成事项和当前 Git 状态。
