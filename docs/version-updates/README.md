# 版本更新文档目录说明

## 目录用途
- 本目录用于保存每个版本的独立更新文档。
- 每个版本文档记录该版本的目标、变更、测试结果和相关提交。

## 文件命名规则
- 文件名必须包含版本号，格式为 `vX.Y.Z.md`。
- 示例：`v0.1.0.md`、`v0.2.0.md`、`v1.0.0.md`。
- 不使用 `latest.md`、`final.md`、`update2.md` 等模糊名称。

## 新版本文档模板
```md
# v0.1.0

## 版本状态
正式上线

## 上线时间
2026-07-26T18:30:00+10:00

## 版本概述
...

## 新增功能
- ...

## 功能调整
- ...

## 问题修复
- ...

## 数据库变化
- 无

## 测试结果
- 构建结果
- 单元测试结果
- 人工验收结果

## 已知问题
- 无

## 相关提交
- 功能 Commit ID
- 文档 Commit ID
```

## 上线时间填写规则
- 仅在版本正式部署到生产环境后填写 `releasedAt`。
- 时间必须使用带时区偏移的 ISO 8601，例如 `2026-07-26T18:30:00+10:00`。
- 不能使用本地开发完成时间、当前时间、文档修改时间或 Git 提交时间冒充上线时间。
- 若版本未正式上线：
  - `status` 使用 `development`
  - `releasedAt` 使用 `null`
  - 页面显示“开发中，尚未上线”

## 版本发布流程
1. 完成功能开发与测试。
2. 确定新版本号。
3. 更新统一版本配置。
4. 创建对应的 `vX.Y.Z.md`。
5. 更新 `docs/VERSION_HISTORY.md` 版本索引。
6. 完成正式部署。
7. 使用真实部署上线时间填写 `releasedAt`。
8. 验证线上版本可访问。
9. 创建版本发布相关 Git commit。
10. 将相关 Commit ID 回填到版本文档。
