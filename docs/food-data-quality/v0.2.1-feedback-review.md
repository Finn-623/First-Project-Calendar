### P0：需要用户复现确认的记录缺陷

#### 4. 删除食物时提示记录缺少有效标记

- 建议ID：`701eda5e-d2b4-421c-af2f-4ad22e813a7c`
- 原始标题：删除食物问题
- 原始描述：删除食物时，会出现食物记录缺少有效标记，刷新后重试。
- 当前状态：pending
- 涉及页面和操作路径：首页 → 已保存餐次 → 食物条目删除按钮 → 确认删除。
- 历史问题表现：删除时没有取得可用于数据库删除的食物记录UUID，页面显示“食物记录缺少有效标识，请刷新后重试”，删除没有完成。
- 当前代码证据：`TodayPage.jsx`会区分餐次UUID与`food_entries` UUID，并在成功写库后才更新前端；`timelineService.deleteFoodEntry`带当前用户约束；固定早餐、午餐、晚餐删除最后食品后保留空餐次，自定义餐次清空后才删除整餐。现有保护仍会在加载出的食物缺少持久化ID时主动报错，因此不能仅凭测试关闭整个反馈。
- 用户最短复现步骤：登录测试账号 → 在真实本日给早餐加入两个食品并确认保存 → 刷新页面 → 删除其中一个食品并确认 → 再刷新页面检查结果；随后对仅剩一个食品的餐次重复一次，验证整餐清理。
- 正常预期结果：首次删除只移除目标食品并立即更新营养汇总；固定三餐删除最后食品后保留空餐次，自定义餐次删除最后食品后整餐消失；刷新后结果保持；全程不出现“缺少有效标识”。
- 异常结果：出现缺少有效标识提示、删除后刷新复原、误删固定餐次/其他食品、自定义餐次留下空卡片，或汇总未更新。
